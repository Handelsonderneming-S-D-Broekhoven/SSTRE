# Notices, SPDX headers and attribution policy

| Field | Value |
|---|---|
| Status | **Proposed** (draft, Phase 0). Requires owner approval together with ADR-0006. Not legal advice. |
| Date | 2026-11-27 |
| Applies to | SSTRE, SSTRE-Engine, SSTRE-AssetCompiler, SSTRE-Manifests, Remaster-Toolkit |
| Evidence | [RD-007 licensing](../research/RD-007-licensing.md) |

## 1. Goals

1. Every file in every SSTRE repository has a machine-readable copyright and license statement, following the [REUSE specification](https://reuse.software/spec/) by FSFE.
2. Upstream and third-party notices are **preserved verbatim**. Nothing is relicensed, and no copyright is claimed that SSTRE does not hold.
3. Each binary or source release ships the notices it needs: license texts, attributions and a GPL corresponding-source offer where applicable.
4. Compliance is checked automatically in CI, using tooling that does not require game data.

## 2. Per-repository license baseline (pending owner confirmation)

| Repo | Default for SSTRE-authored files | Exceptions |
|---|---|---|
| SSTRE | `GPL-3.0-only` | `schemas/**`: `CC0-1.0`. Docs may use `CC-BY-SA-4.0` if the owner chooses |
| SSTRE-Engine | **upstream license preserved**: `GPL-2.0-only`. New SSTRE files `GPL-2.0-only` (or `GPL-2.0-or-later` if the owner approves) | upstream third-party files keep their own IDs (`Zlib`, `BSD-3-Clause`, `MIT`, `Apache-2.0`, `LicenseRef-*`) |
| SSTRE-AssetCompiler | `GPL-3.0-only` | synthetic test fixtures: `CC0-1.0` |
| SSTRE-Manifests | `CC-BY-SA-4.0` for curated recipes/mappings. `CC0-1.0` for schemas and generated lock files | scripts (if any): `GPL-3.0-only` |
| Remaster-Toolkit | `GPL-3.0-only` | fixtures: `CC0-1.0` |

`-only` vs `-or-later` is an open owner decision (RD-007 §6.2). Replace the IDs above consistently once it is decided.

## 3. File-level rules

### 3.1 New files written by SSTRE contributors

Use REUSE-style SPDX tags in a comment at the top of each file:

```text
SPDX-FileCopyrightText: <year> <copyright holder>
SPDX-License-Identifier: GPL-3.0-only
```

- The copyright holder is the contributor, or the owner if the contributor assigned rights or worked under contract. The owner decides the default wording (RD-007 Q11). Do not invent holders.
- Files that cannot carry comments (JSON, images, binary fixtures) are covered by a `REUSE.toml` annotation, or a `<file>.license` sidecar.
- Generated files carry the license of their generator's *input* data plus a `# generated by <tool> <version>; do not edit` note. Generated lock manifests are `CC0-1.0` by default.

### 3.2 Upstream engine files (SSTRE-Engine)

- **Do not edit, reformat or remove** existing Croteam/fork headers ("…under the terms of version 2 of the GNU General Public License…"). Do not prepend SPDX lines to unmodified upstream files. Declare them in `REUSE.toml` instead (path globs → `GPL-2.0-only`, holder "Croteam Ltd." etc. as stated in the files).
- When modifying an upstream file, keep its header and **add** a line below it: `Modifications Copyright (C) <year> <holder>` (GPLv2 §2(a) requires prominent notice of changes and the date). Record notable changes in `docs/sstre/CHANGES.md`.
- Known non-GPL upstream paths and their proposed identifiers (verify at import time):

| Path (Croteam layout) | SPDX ID | Status |
|---|---|---|
| `Sources/Engine/zlib/**` | `Zlib` | ok |
| `Sources/libogg/**`, `Sources/libvorbis/**` | `BSD-3-Clause` | ok, attribution required |
| `Sources/LWSkaExporter/SDK/**` | `LicenseRef-NewTek-LWSDK` | **terms unknown**. Exclude from builds. Removal pending counsel (RD-007 Q9) |
| `Sources/Engine/Sound/DSOUND.H` | `LicenseRef-Microsoft-DirectSound-Header` | **terms unknown**. Pending counsel |
| `**/bison.simple`, bison-generated `Parser.cpp` | `GPL-2.0-or-later` WITH the Bison 1.24 special exception (verify the SPDX exception ID) | ok |
| `Sources/Engine/GameAgent/MSLegacy.h` | `GPL-2.0-or-later` | ok |
| `Sources/Entities/**` (TFE, RT/Vk forks) | **undetermined** | provenance question (RD-007 Q4) |
| `SE1_10.gro` | `LicenseRef-Croteam-SE1-Resources` (unknown) | do not redistribute separately. Pending Q5 |
| RTGL1 `Source/KTX/**` | `Apache-2.0` (and KTX's own `LicenseRef-*`) | GPLv2 compatibility question (RD-007 Q1) |
| RTGL1 `Source/FSR2/**` | `MIT` | prefer building from source |

- License texts for every ID used go in `LICENSES/<SPDX-ID>.txt` (REUSE layout). Keep the upstream top-level `LICENSE` file **unchanged** as well.

### 3.3 Forbidden content (all repos)

- Game files, extracted or converted assets, AI-generated derivatives of game assets, screenshots of restricted content, model weights, proprietary SDKs (DLSS/NGX/NRD, console SDKs), and secrets.
- Files whose license is unknown, unless they are pre-existing upstream engine files recorded in the table above.
- `NC`, research-only or unlicensed model or checkpoint references in release lock manifests. Dev-only use must be marked explicitly (RD-007 §8).

## 4. `THIRD_PARTY_NOTICES.md`

Each repository that **ships, vendors, pins or downloads** third-party components keeps a `THIRD_PARTY_NOTICES.md` at its root. One section per component:

```markdown
### <Component name> <version or commit>
- Source: <URL>  (pinned: <commit / tag / sha256>)
- License: <SPDX ID>  (text: LICENSES/<SPDX-ID>.txt)
- Copyright: <verbatim copyright lines from upstream>
- Used as: vendored source | submodule | build-time tool | runtime download | separate process
- Shipped in: source release | binary release | not shipped
- Notes: <modifications, NOTICE file contents (Apache-2.0 §4(d)), attribution text required by license>
```

Rules:
- Copyright lines are **copied verbatim** from upstream (`LICENSE`, `COPYING`, `NOTICE`, headers). If they cannot be found, write "not stated upstream" instead of guessing.
- Apache-2.0 components: reproduce upstream `NOTICE` content where it exists.
- Model weights the user downloads: list them under a separate heading, "User-downloaded models (not redistributed)", with license ID, URL, revision hash and required use restrictions (e.g. OpenRAIL++-M Attachment A must be passed on).
- The umbrella repo's `THIRD_PARTY_NOTICES.md` links to each sibling repo's file and lists only components the umbrella itself pins or ships (e.g. the builder's dependencies).

## 5. Release artefacts

Every binary release (engine or tool bundle) contains:
1. `LICENSES/` with every license text that applies to the shipped files.
2. `THIRD_PARTY_NOTICES.md` (or a generated `.txt`/SPDX SBOM) for the shipped components.
3. For GPL binaries: the complete corresponding source for the exact commit (tag plus source archive), or a GPLv2 §3(b) / GPLv3 §6 offer. Hosting the source next to the binary on the same release page is preferred.
4. The README **disclaimer**: *"SSTRE is an unofficial, fan-made project. It is not affiliated with, endorsed by, or sponsored by Croteam or Devolver Digital. Serious Sam is a trademark of its respective owner(s). No game assets are included; you need a legally acquired copy of the game."*
5. No Croteam/Devolver logos, key art or game assets.
6. An SBOM (SPDX 2.3 or later, JSON) generated by the REUSE tool or ScanCode. Optional at first, but recommended from the first public binary release.

Bundles that combine the engine and the GPL-3.0 tools are **aggregates**. Each component keeps its own license, and nothing is statically or dynamically linked across the GPL-2.0-only / GPL-3.0 boundary (RD-007 §5).

## 6. Tooling (proposed; nothing installed in Phase 0)

| Tool | Purpose | Where | Notes |
|---|---|---|---|
| [REUSE tool](https://codeberg.org/fsfe/reuse-tool) (`reuse lint`, `reuse spdx`) | verify every file has license and copyright info. Generate an SPDX SBOM | CI on all five repos (pin the version and the action/container by digest) | primary gate. For SSTRE-Engine, run on SSTRE-authored paths first. Upstream gaps are listed as known deviations |
| [ScanCode Toolkit](https://github.com/aboutcode-org/scancode-toolkit) | deep detection of license text in vendored code and dependencies | manual or scheduled job on engine imports and dependency bumps | slow. Use for audits (RD-007 experiment E1), not every PR |
| [licensee](https://github.com/licensee/licensee) (MIT) | detect the top-level license of a repo or dependency | quick check in dependency-review scripts | top-level only |
| Dependency-license check for Python (e.g. `pip-licenses`) | flag GPLv3-incompatible or unknown Python dependencies in AssetCompiler/Toolkit | CI on lockfile changes | choose once the Python packaging is decided |
| Build-flag guard (custom script) | fail if `RG_WITH_NVIDIA_DLSS`, NGX or NRD paths are enabled in release configs | SSTRE-Engine CI | RD-007 risk R2 |
| Model-license check (custom, schema-driven) | reject lock manifests whose models lack `license`/`license_url` or are on the deny-list | Manifests/Toolkit CI | depends on the RD-004 provenance schema |

Untrusted upstream code is never executed for these checks. The scanners only read files (plan §5).

## 7. Process

1. **New dependency or vendored file:** the PR must add or extend the `THIRD_PARTY_NOTICES.md` entry and the `LICENSES/` text. A reviewer checks compatibility against the repo baseline (§2) and the RD-007 compatibility notes. An unknown or incompatible license blocks the merge.
2. **Engine upstream sync:** re-run ScanCode on the diff and update `REUSE.toml` and the deviations table.
3. **Release:** the release checklist (RD-008) includes `reuse lint` passing, the notices up to date, the corresponding-source archive attached, and the disclaimer present.
4. **Questions:** anything that needs a legal judgment is recorded in RD-007 §16 and is not resolved in a PR.
